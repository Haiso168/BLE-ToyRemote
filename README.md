# YCM 遥控器 —— 比官方小程序更自由的 Android 控制 App

针对蓝牙玩具 **YCM-BL001** 的第三方 Android 客户端。协议来自官方小程序逆向，
并已通过真机实测验证（`AA 01 02 AD` 等指令可正常控制）。

本工程覆盖**阶段 1+2**：完整 BLE 链路 + 手动控制页 + 波形编排页 + 命令探测页。

---

## 它比官方小程序强在哪

| 能力 | 官方小程序 | 本 App |
|---|---|---|
| 模式切换 | ✅ 10 个 | ✅ 10 个 |
| 力度范围 | 仅 35~100 | **0~100 全范围**（实测固件支持） |
| 力度变化时序 | ❌ 只能单点 | ✅ **自定义波形：爬升/脉冲/心跳/阶梯/呼吸，可循环** |
| 摇晃控制 | 固定映射 | ✅ 可调、带节流 |
| 急停 | 需翻页 | ✅ 常驻大按钮 |
| 预设保存 | ❌ | ⏳ 待做（阶段 4） |
| 离线可用 | ❌ 依赖微信+网络 | ✅ 完全离线 |
| 命令空间探测 | ❌ | ✅ 内置遍历工具 |

**必须明确的边界**：10 个模式的具体振动曲线固化在玩具固件里，协议只传"用第几号"。
所以"自定义"的真实含义是 **自由编排模式切换与力度变化的时序**，而不是改造模式本身。
这恰恰是官方最弱的地方——它的"摇晃"和"滑条"只是两个很粗糙的时序控制器。

## 协议速查（已实测）

| 项目 | 值 |
|---|---|
| 广播名 | `YCM-BL001` |
| Service | `0000AE3A-0000-1000-8000-00805F9B34FB` |
| 写特征 | `0000AE3B-...`（**只有 WRITE NO RESPONSE**） |
| 通知特征 | `0000AE3C-...`（**只有 NOTIFY，不可 Read**） |

**帧格式**：`AA | group | cmd | [param] | checksum`，`checksum = 前 N-1 字节之和 & 0xFF`

| group | cmd | 含义 |
|---|---|---|
| 0x01 | 0x00 / 0x01 | 暂停 / 开始 |
| 0x01 | 0x02~0x09, 0x10, 0x11 | 模式1~10（微风/心跳/冲击/拍打/深度/宇宙/海啸/瀑布/火山/神风） |
| 0x02 | 0x12 + param | 力度（param = 力度值） |

**实测要点**：

- 连接后**不需要**订阅通知、**不需要**发开机帧，直接写 `AE3B` 即生效
- 订阅 `AE3C` 会让玩具震一下（小程序连上就震的原因就是它自动订阅了）
- Android 无需系统配对即可连接（Windows 10 则必须先配对，两者不同）
- Android 13+ 用 `writeCharacteristic(char, bytes, WRITE_TYPE_NO_RESPONSE)`；
  旧版本用 `char.value = ...; gatt.writeCharacteristic(char)`

## 编译运行

### 前置

- **Android Studio** Ladybug (2024.2) 或更新
- **JDK 17**（Android Studio 自带）
- Android SDK：**compileSdk 34**、**minSdk 24**
- 手机 Android 7.0 及以上

### 步骤

1. Android Studio → **Open** → 选择本目录 `YcmRemote`（不是整个工作区）
2. 等待 Gradle Sync 完成（首次会下载依赖）
3. 手机开启开发者选项 + USB 调试，连上电脑
4. 点 **Run ▶**

如果 Gradle 版本不匹配，Android Studio 会提示自动升级 AGP/Gradle，点同意即可。
本工程的版本组合是 AGP 8.5.2 + Kotlin 2.0.20 + Compose BOM 2024.09.00，可按提示上调。

### 权限

首次运行会申请：

- Android 12+：`BLUETOOTH_SCAN`、`BLUETOOTH_CONNECT`（"附近的设备"）
- Android 11 及以下：`ACCESS_FINE_LOCATION`

**拒绝权限会导致扫描不到任何设备**，且系统不会提示原因。

## 使用

### ① 连接页

点「扫描设备」→ 列表里找 **YCM-BL001**（会高亮）→ 点「连接」。
连上后顶部状态变成 **已就绪**。

日志区会显示每一步：连接状态、服务发现、写特征属性、写入结果、收到的通知。

### ② 控制页

- **急停**：最大按钮，任何时刻可拍
- **模式**：10 个 chip，点一下立即切
- **力度**：滑条 0~100（真机实测的完整范围）+「发送力度」+「归零」
- **摇晃控制**：打开后晃动手机实时控制力度
  - 用**线性加速度**（先低通滤波估出重力再扣除），所以**静止就是 0**，不会一开机就满速
  - 有死区（0.35 m/s²）避免轻微抖动乱发指令
  - 内置节流：至少 100ms 间隔且变化 ≥2 才发送
  - 静止 500ms 后自动归零
  - **灵敏度**可调（0.5~12）：数值越小越灵敏。震一下就到底就往左调，晃半天没反应就往右调
  - 面板上有「实时力度」显示，方便边调边看
- **AE3C 回包**：原样显示收到的通知（格式尚未解析）

### ③ 波形页（核心功能）

脚本格式，每行一步 `力度 [持续毫秒]`：

```
# 缓慢爬升再回落
40  400
55  400
70  500
85  600
100 1500
70  400
50  300
0   200
```

规则：

- `力度 0` = 暂停（发 `AA 01 00 AB`）
- 省略毫秒数默认 300
- `#` 之后是注释
- 力度范围 **0~100**（实测有效值）；脚本解析器允许写到 255，便于超出范围试探
- 可勾选**无限循环**，或设置 1~20 次重复

内置 5 个示例：爬升 / 脉冲 / 心跳 / 阶梯 / 呼吸。点 chip 一键填入，改完点「播放」。

**写入频率提醒**：BLE 单次写入有开销，`BleManager` 里设了 20ms 最小间隔。
步长低于 ~50ms 意义不大，协程会堆积。

### 命令空间探测（找隐藏功能）

校验和只是求和，**固件无法用它做白名单过滤**，所以遍历未知命令字是安全的。

已知：组 `0x01` 的 `0/1/2~9/16/17` 有定义，其余空白。工具支持：

- 选命令组（0~8）
- 选命令字范围
- 选每步间隔（200~3000ms）

点「开始遍历」后会逐个发送，**需要你人工观察玩具反应**，记下哪个编号有动作。
中途可按「中止」断开。

> ⚠️ 这会真的驱动玩具，请只在安全环境下使用。出现异常立刻按急停。

值得单独试探的方向：

- 力度 `0~34` 的确切行为（是停止，还是有最低档？）
- 力度 `101~255` 是被截断、映射，还是无效
- 命令组 `0x03` / `0x04` 下有没有东西

## 代码结构

```
app/src/main/java/com/ycm/remote/
├── MainActivity.kt              入口 + 底部导航 + 权限申请
├── protocol/
│   ├── Protocol.kt              帧编码/校验/HEX 解析（纯逻辑，无 Android 依赖）
│   └── Pattern.kt               波形数据模型 + 脚本解析 + 内置示例
├── ble/
│   ├── BleManager.kt            扫描/连接/服务发现/写入/通知（StateFlow 暴露状态）
│   └── PatternPlayer.kt         时序引擎（协程驱动，可中断）
└── ui/
    ├── ConnectionScreen.kt      连接页
    ├── ControlScreen.kt         手动控制页
    ├── PatternScreen.kt         波形 + 原始帧 + 命令探测
    └── theme/Theme.kt           Material3 主题（支持动态取色）
```

设计取舍：

- **Protocol.kt 不依赖 Android**，纯 Kotlin，方便单元测试和跨平台复用
- 状态用 `StateFlow` 暴露，UI 用 `collectAsStateWithLifecycle` 收集
- 写入带**最小间隔保护**和**重试**，避免高频调用压垮 BLE 栈
- 波形播放结束**自动发暂停**兜底

## 真机实测记录与修复

### v1.0 —— 2026-10-02，首次编译通过并实测可控制

构建方式：GitHub Actions 云端编译（本机无 Android SDK）。
真机结果：**能正常连接并控制玩具**。

首次构建遇到并修复的问题：

| 问题 | 原因 | 修复 |
|---|---|---|
| CI 报 `No such file or directory: .../YcmRemote` | 工作流写死了子目录，但仓库根就是工程根 | 改为自动探测工程目录 |
| `Compose Compiler Gradle plugin is required` | Kotlin 2.0 起 Compose 编译器独立发版，必须显式应用插件 | 加 `org.jetbrains.kotlin.plugin.compose`（版本与 Kotlin 一致） |

### v1.1 —— 依据实测反馈的改进

用户实测反馈 4 项，全部修复：

| # | 反馈 | 原因 | 修复 |
|---|---|---|---|
| 0 | 力度范围是 0-100，不是 35-100 | 官方小程序人为限制到 35 起，固件本身支持 0-100 | 常量改为 `STRENGTH_MIN=0 / STRENGTH_MAX=100`，滑条铺满，去掉「实验范围」开关 |
| 1 | 翻转手机后页面刷新、连接断开 | 旋转屏幕销毁重建 Activity，而 `BleManager` 是 Activity 局部对象 | Manifest 锁定 `screenOrientation="portrait"` + `configChanges` 抑制重建 |
| 2 | 摇晃控制一开就到最大 | 原公式用**原始**加速度，静止时含重力（≈9.8）就已接近满值 | 改用**线性加速度**：低通滤波估重力后扣除，静止为 0；加死区、`0-100` 线性映射、可调灵敏度（0.5~12）、实时值显示 |
| 3 | 底部菜单序号改成图标 | 首版为规避图标依赖缺失用了 `①②③` | 加回 `material-icons-extended`，换 `Bluetooth` / `Tune` / `GraphicEq` |

### v1.2 —— UI 分区重构 + 摇晃阈值

| # | 反馈 | 修复 |
|---|---|---|
| 1 | 各功能之间 UI 分界不明显 | 新增 [`SectionCard`](app/src/main/java/com/ycm/remote/ui/SectionCard.kt) 统一分区卡片（图标+标题+副标题+内容区，圆角+弱底色），三个页面全部重构：控制页按「急停 / 启停 / 模式 / 力度 / 摇晃 / 调试信息」分区；连接页按「权限 / 蓝牙 / 连接状态 / 设备列表 / 日志」分区；波形页按「波形编辑 / 播放 / 原始帧 / 命令探测」分区。急停与探测用红色 accent 跳出 |
| 2 | 摇晃需要最小阈值，默认 15 | 新增可调阈值滑条（0-100，默认 15）：算出的力度 **≥ 阈值才发送**，低于阈值按停止处理。同时把发送逻辑改成「值变化才发」，停顿只在"从有到无"时发一次暂停，减少无效写入 |

## 安全提醒

这是控制实体设备的 App：

- 波形步长别设太短，写入间隔别低于 50ms
- 探测未知命令时人在旁边，随时能断电
- 首次跑新波形时先把时长设短
